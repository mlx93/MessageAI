# Read Receipt Investigation Prompt

## Problem Statement

We have a React Native messaging app where read receipts ("Read [time]") are not appearing for senders even though the recipient is viewing the message. The specific scenario is: User A sends a message, User B is on the conversations page (Messages list at `app/(tabs)/index.tsx`) and sees the message preview, but User A does not see a "Read [time]" receipt below their sent message. The read receipt flow should work as follows: when User B views a message (either in the chat screen or on the conversations page), `markMessagesAsRead` in `services/messageService.ts` (lines 176-194) should update the message's `readBy` array in Firestore to include User B's UID, which triggers the Firestore listener in `app/chat/[id].tsx` (lines 408-575) to update the message state, causing `formatReadReceipt` (lines 1018-1043) to return a non-null string, which is then rendered below blue bubbles (lines 1747-1753 for own messages). However, we suspect the issue is that `markMessagesAsRead` is ONLY called when a user is actively IN the chat screen (lines 567-574), NOT when they're viewing message previews on the conversations list, meaning messages viewed on the conversations page never get marked as read in Firestore.

## Required Investigation

Please investigate the complete read receipt pipeline by examining: (1) Whether `markMessagesAsRead` is being called when users view messages on the conversations page—check if `app/(tabs)/index.tsx` has any logic to mark messages as read when conversation previews are tapped or viewed, and verify if `services/globalMessageListener.ts` (the global message listener that shows in-app notifications) marks messages as read when they arrive while the user is on the conversations page; (2) The Firestore listener update logic in `app/chat/[id].tsx` lines 510-532 which checks if `readBy` arrays have changed and should trigger re-renders—add console.log statements to verify if the readBy array is actually being updated in Firestore when the recipient views the message (check Firebase console directly), and confirm the MessageRow memo comparison at lines 1912-1917 properly detects readBy changes using the `.some()` comparison we added; (3) The `formatReadReceipt` function (lines 1018-1043) to understand why it might return null—verify that `message.readBy` contains more than just the sender's UID (should have length > 1), check if `otherReaders` is properly filtering out the sender, and note that the function uses a placeholder approximation (`timestamp + 1 minute`) instead of actual readAt timestamps which means the "Read" time shown is inaccurate; and (4) The read receipt rendering conditions at lines 1747-1753 which require BOTH `readReceipt` to be non-null AND `isLastInGroup` to be true—verify this `isLastInGroup` condition isn't preventing display, especially for single messages or the last message in a conversation. The most likely root cause is that messages are NOT being marked as read in Firestore when viewed on the conversations page (only when viewed in the chat screen), so implement a solution that calls `markMessagesAsRead` when: (a) User taps a conversation in the list to open it, (b) User views a message preview with unread badge, or (c) Global message listener receives a message while user is on conversations page and conversation is visible.
