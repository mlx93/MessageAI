# Priority Badge Investigation & Resolution Prompt

## Problem Statement

The system uses client-side keyword detection (in `utils/priorityDetector.ts`) that runs instantly (<1ms) and writes priority fields to optimistic messages on the sender side. A Cloud Function (`detectPriorityOnMessage`) then refines these priorities using GPT-4o-mini and writes back to Firestore. The frontend subscribes via `subscribeToMessagesPaginated` in `services/messageService.ts` and renders badges using the `PriorityBadge` component. **Current Issues:** (1) On sender side, the urgent badge appears instantly but disappears within 1 second and only reappears when leaving/returning to the chat screen, (2) New messages don't auto-scroll to bottom when sent, (3) On receiver side, badges don't appear until leaving/returning to the screen even though the Cloud Function is writing priority fields to Firestore within 2-5 seconds. The root causes appear to be: (a) the Firestore listener in `app/chat/[id].tsx` (lines 388-485) is overwriting client-detected priorities despite preservation logic at lines 441-453, (b) the receiver side has no client-side detection running at all, and (c) React's memo optimization in `MessageRow` (lines 1796-1815) might be preventing re-renders when priority fields arrive from Firestore.
