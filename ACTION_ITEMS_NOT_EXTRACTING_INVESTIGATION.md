# Action Items Not Extracting - Investigation Prompt

The Action Items extraction is completing successfully but returning 0 items for all 6 analyzed conversations, even though we know there should be actionable content. The logs show `✅ Extracted 0 action items from [conversationId]` for every conversation processed. The duplicate detection logic only checks against PENDING items (not completed/deleted), and we recently fixed the resurrection logic to create NEW items when finding completed/deleted matches, so those shouldn't be blocking extraction. However, the AI isn't finding any action items at all in the conversations.

## Investigation Requirements

First, check the backend Cloud Function logs in Firebase Console for the `extractActions` function to see if there are any errors or warnings during AI processing. Look for logs showing how many messages were retrieved from each conversation - the function queries up to 200 messages per conversation, filters out deleted/hidden messages, and passes them to GPT-4o for extraction. Verify that: (1) messages are actually being retrieved (check for "Messages:" or message count logs), (2) the messages have valid text content and aren't empty, (3) the AI is receiving the messages in the correct format `[index] sender: text`, and (4) there are no token limit errors or AI API failures. Also check if a `dateRange` parameter is being passed from the frontend that might be filtering out all messages - the frontend `handleAnalyze` function (lines 152-223 in `app/ava/action-items.tsx`) doesn't pass any dateRange, so all messages should be included.

## Root Cause Hypotheses

The most likely causes are: (1) **No messages in conversations** - the 200-message query is returning empty results because messages were deleted, hidden, or the subcollection path is incorrect, (2) **AI not detecting action items** - the messages exist but don't contain clear actionable content that matches the extraction patterns ("I'll handle X", "Can you do Y?", "TODO:", etc.), or the AI's confidence threshold is too high, (3) **Date range filtering** - although the frontend doesn't pass a dateRange, check if there's default filtering in the backend that excludes all messages (unlikely but possible), or (4) **Firestore query issues** - the query `conversations/${conversationId}/messages` with filters `where("deleted", "!=", true)` might not be matching any documents due to index issues or field inconsistencies. To diagnose, add detailed logging in `functions/src/ai/actionItems.ts` around line 114 to log the actual message count retrieved, and around line 138 to log the prompt sent to the AI including sample messages. This will reveal whether the issue is at the query level (no messages) or AI level (messages exist but not extracting).
