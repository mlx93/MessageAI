# Action Items Display & UX Improvements - Implementation Prompt

## Overview
The action items feature needs improvements to its visibility logic, duplicate detection, and user experience. Currently, users only see items assigned to them or unassigned items, but they should see ALL action items from conversations they participate in, with visual hierarchy to prioritize their own items.

## Core Requirements

**Visibility & Filtering:** Modify the action items display logic in `app/ava/action-items.tsx` (lines 51-60) to show action items from ALL conversations where the current user is a participant, regardless of who the item is assigned to. Remove the current filter `data.assigneeId === userId || !data.assigneeId` and instead query the user's conversations first, then show all pending action items from those conversations. Display the user's own action items at the top with a distinctive background color (e.g., light blue `#E8F2FF` like the selected state), followed by items assigned to other participants in those same conversations. The backend's default assignment logic (lines 276-282 in `functions/src/ai/actionItems.ts`) should be removed - leave `assigneeId` and `finalAssignee` as `null` when no assignee is determined, allowing items to be visible to all conversation participants.

**Smart Duplicate Detection:** Update the duplicate detection in `functions/src/ai/actionItems.ts` (lines 196-210 and 292-307) to ONLY check against action items with `status: 'pending'`. If an extracted action item matches a completed or deleted item (same task, messageId, and assigneeId), either create a new pending item or update the existing item's status back to 'pending' with a new `createdAt` timestamp. This ensures users can re-extract action items from old conversations without being blocked by historical data. The query at line 198 should remain `where("status", "==", "pending")` and the duplicate check should explicitly only compare against this filtered set.

**Action Item Detail View:** Create a new screen at `app/ava/action-item-detail/[id].tsx` (mirroring the pattern from `app/decision/[id].tsx`) that displays comprehensive context about an action item. When a user taps the "View" link on an item, navigate to this detail page showing: (1) the action item details (task, assignee, deadline, confidence), (2) the source message that triggered the extraction with highlighting, (3) 3-5 messages before and after for context (similar to decision detail view lines 200-300), (4) conversation participants and metadata, and (5) a button to mark the item complete or navigate to the full conversation. Update the `onPress` handler in `action-items.tsx` line 401 from `router.push(\`/chat/${item.conversationId}\`)` to `router.push(\`/ava/action-item-detail/${item.id}\`)`.

## Technical Details
The sorting logic should use a combination of `assigneeId === userId` as the primary sort key (true values first) followed by `createdAt` timestamp. The styling for personal items should use the existing `itemCardSelected` style (line 709) or create a new `itemCardPersonal` style with the same blue tint. For the duplicate resurrection feature, prefer updating the existing item's status over creating duplicates - use `updateDoc` to set `status: 'pending'`, remove `completedAt`/`deletedAt`, and set `createdAt: serverTimestamp()`. The action item detail view should reuse the message rendering components and context-fetching logic already established in the decisions detail screen to maintain UI consistency.
